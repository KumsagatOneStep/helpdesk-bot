# Helpdesk-бот: голосовой ввод для задач — дизайн

Дата: 2026-10-09. Статус: на ревью.

Вторая из трёх частей доработки (первая — внутренние задачи, `2026-10-09-internal-tasks-design.md`; третья — склад ноутбуков, проектируется отдельно). Ветка `voice-input` от `internal-tasks`.

## 1. Цель

Специалист может вместо текста отправить голосовое — бот распознаёт речь (русский, казахский, смесь) и использует текст:
- в **описании** при создании задачи — с подтверждением;
- в **комментарии** к задаче — без подтверждения, аудио + текст.

**Критерии успеха**
- Голосовое на шаге «Описание» → через несколько секунд бот показывает распознанный текст с кнопками [✅ Подходит] [✏️ Исправить]; «Подходит» делает его описанием.
- Голосовой комментарий участники получают аудио с подписью-расшифровкой.
- Голос не покидает сервер.
- Бот не «замирает» на время распознавания; при выключенном или упавшем распознавании всё работает как раньше, только без текста.

**Решения пользователя**
| Вопрос | Решение |
|---|---|
| Где голос | Описание при создании задачи и комментарии к задачам (вариант «Б»); ответы пользователям WhatsApp не трогаем |
| Где распознавать | Локально, Whisper на сервере (`faster-whisper`) — данные остаются на сервере |
| Встраивание | Внутри процесса бота, без отдельного сервиса |
| После распознавания (описание) | Показать текст, кнопки [✅ Подходит] [✏️ Исправить] |
| После распознавания (комментарий) | Без подтверждения: аудио + текст |

**Вне рамок:** голос в ответах пользователям WhatsApp, распознавание входящих голосовых от пользователей, выбор языка вручную, отдельный STT-сервис, облачные распознаватели (интерфейс позволяет добавить позже).

## 2. Устройство

### Модуль `helpdesk/stt.py`

```python
class Transcriber(Protocol):
    async def transcribe(self, path: str) -> str | None: ...
```

- `None` — не удалось (пусто, только шум, исключение внутри модели). Исключения наружу не выходят, логируются.
- `WhisperTranscriber(model_name, download_root)`:
  - модель `faster_whisper.WhisperModel(model_name, device="cpu", compute_type="int8", download_root=...)` загружается лениво при первом вызове и держится в памяти; `download_root = <FILES_DIR родитель>/models` → в Docker `/data/models` (переживает перезапуски);
  - распознавание — `asyncio.to_thread(...)` под `asyncio.Lock` (одно голосовое за раз);
  - язык — автоопределение; сегменты склеиваются, текст `strip()`, пустая строка → `None`;
  - `is_loaded` — свойство: загружена ли модель (для сообщения «загружаю модель»).
- `DisabledTranscriber` — всегда `None`, `is_loaded=True`.
- `make_transcriber(settings) -> Transcriber` — по `stt_enabled`.

Transcriber кладётся в `dp["stt"]` в `main.py` и приходит в обработчики аргументом `stt`, как `settings`.

### Настройки (`config.py`, `.env.example`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `STT_ENABLED` | `true` | выключатель распознавания |
| `STT_MODEL` | `small` | `base` / `small` / `medium` (качество ↔ память и скорость) |
| `STT_MAX_SECONDS` | `120` | голосовые длиннее не распознаются |

Требование к серверу при `small`: от 4 ГБ RAM на VPS (модель ~1 ГБ в памяти). Образ бота растёт примерно на 300 МБ (`faster-whisper` + `ctranslate2` + `av`); ffmpeg не нужен — ogg/opus декодирует PyAV.

### Общий шаг обработки голосового (`telegram/voice.py`)

`async def recognize(message, bot, settings, stt) -> VoiceResult`:
1. длительность `message.voice.duration` (или `audio.duration`) > `stt_max_seconds` → `VoiceResult(status="too_long", content=None, text=None)` **без скачивания** — но для комментария файл всё равно нужен (см. 3.2), поэтому функция принимает флаг `download_if_too_long`;
2. скачать через существующий `extract_content` (лимит 20 МБ → `FileTooBig` как сейчас);
3. если модель ещё не загружена — ответить «⏳ Загружаю модель распознавания (один раз)…», иначе «⏳ Распознаю…» (это сообщение потом редактируется);
4. `text = await stt.transcribe(path)` → `status="ok"` или `"failed"`.

`VoiceResult(status, content: Content | None, text: str | None, progress: Message | None)`.

База данных не меняется: голосовой комментарий — `task_comments.kind="audio"`, файл, `text` = расшифровка (или `None`).

## 3. Сценарии

### 3.1 Описание при создании задачи

Шаг `TaskForm.description` дополнительно принимает `voice` / `audio` (новый обработчик до `bad_description` и `stray_input`).

- `too_long` → «Голосовое длиннее 2 мин — напишите текстом.», остаёмся на шаге.
- `failed` → прогресс-сообщение меняется на «Не удалось распознать — напишите текстом или запишите ещё раз.», остаёмся на шаге.
- `ok` → текст обрезается до 2000 символов (если обрезан — пометка «(обрезано до 2000 символов)»), сохраняется в FSM как `stt_text`; голосовое сохраняется вложением (`file_kind="voice"`), **только если вложения ещё нет**; новое состояние `TaskForm.description_confirm`; прогресс-сообщение меняется на:
  ```
  🎤 Распознано:
  «<текст>»
  [✅ Подходит] [✏️ Исправить]
  ```
- `tkn_stt_ok` (в `description_confirm`) → `description = stt_text`, дальше шаг «Для кого».
- `tkn_stt_edit` (в `description_confirm`) → «Отправьте описание текстом или запишите голосовое заново.», назад в `TaskForm.description`; уже сохранённое голосовое-вложение остаётся.
- В `description_confirm` текст или голосовое тоже принимаются (как на шаге «Описание») — человек может сразу переписать, не нажимая кнопку.
- Кнопки не на своём шаге → `stale_dialog` («Диалог уже завершён»). Меню/команды/«Отмена» — как в остальных шагах (`leave_dialog`, `menu_cancel`); `stray_input` ловит прочее.

### 3.2 Комментарий к задаче

В `_comment_task` (reply на сообщение задачи), если сообщение — голосовое/аудио:
- распознать (`download_if_too_long=True` — файл нужен для пересылки);
- комментарий сохраняется с `text` = расшифровка (или `None`);
- участникам: аудио с подписью «💬 З-12 · Ерлан (🎤): <текст>» или «💬 З-12 · Ерлан (🎤)», если текста нет;
- автору: прогресс-сообщение меняется на «💬 → З-12 ✓» и, если распознано, «🎤 <текст>».

`tasks.service.comment` получает необязательный флаг `voice: bool = False`, добавляющий «(🎤)» к имени в подписи. Остальная логика `comment` не меняется.

Голосовые-ответы пользователям WhatsApp (reply на заявку или активная заявка) — без изменений.

### 3.3 Ошибки

| Ситуация | Описание задачи | Комментарий |
|---|---|---|
| длиннее `STT_MAX_SECONDS` | просьба написать текстом | аудио без расшифровки |
| распознавание пустое/упало | просьба написать или записать заново | аудио без расшифровки |
| файл > 20 МБ | «бот не может его скачать» (как сейчас) | то же |
| `STT_ENABLED=false` | «Распознавание выключено — напишите текстом.» | аудио без расшифровки |
| два голосовых одновременно | второе ждёт (Lock) | то же |

## 4. Тестирование

TDD; в тестах — `FakeTranscriber(text | None, loaded=True)`, настоящая модель не загружается.

- `stt`: `DisabledTranscriber` → `None`; `WhisperTranscriber` с подменённым `WhisperModel` (monkeypatch): склейка сегментов, пустой результат → `None`, исключение модели → `None`, модель создаётся один раз, `is_loaded` меняется после первого вызова; `make_transcriber` по настройке.
- `voice.recognize`: длинное без скачивания; длинное со скачиванием для комментария; ok; failed; сообщение «загружаю модель» при `loaded=False`.
- диалог: голос в описании → подтверждение → «Подходит» → задача с описанием и голосовым вложением; «Исправить» → назад к описанию; не распознано → остаёмся; длинное → остаёмся; фото до голоса — вложение остаётся фото; обрезка 2000; кнопки `tkn_stt_*` вне шага → `stale_dialog`; сортировка обработчиков: голос в `description`/`description_confirm` не уходит в `stray_input`.
- комментарий: голос с расшифровкой → подпись с текстом и «(🎤)»; без расшифровки → подпись без текста; ни одной строки outbox `wa`.
- настройки: значения по умолчанию.

Ручная проверка на Mac: реальное голосовое на русском и казахском, время распознавания, размер `data/models`.

## 5. Развёртывание

- `uv add faster-whisper`; образ пересобирается.
- Первое голосовое скачивает модель в `data/models` (~500 МБ для `small`), бот предупреждает об этом.
- На слабом сервере: `STT_MODEL=base` или `STT_ENABLED=false`.
