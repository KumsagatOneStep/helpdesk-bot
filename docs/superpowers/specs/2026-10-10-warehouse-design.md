# Helpdesk-бот: склад техники и расходников — дизайн

Дата: 2026-10-10. Статус: на ревью.

Третья из трёх частей доработки (первая — внутренние задачи, вторая — голосовой ввод). Изначально задумывался как «склад ноутбуков»; по решению пользователя расширен на всю технику и расходники. Ветка `warehouse` от `voice-input`.

## 1. Цель

Специалисты видят в боте, что есть на складе, и сами списывают взятое; координатор ведёт приход и позиции; когда что-то заканчивается, координатор получает предупреждение.

**Критерии успеха**
- Специалист за 3–4 нажатия узнаёт, есть ли «картридж 85A», и берёт его — остаток уменьшается, в истории видно, кто взял.
- Координатор вносит начальные остатки одним xlsx-файлом, дальше ведёт приход кнопками.
- При падении остатка до минимума координаторы получают одно сообщение.
- Остаток никогда не уходит в минус, даже при одновременных выдачах.
- «📥 Склад.xlsx» — остатки и вся история движения.

**Решения пользователя**
| Вопрос | Решение |
|---|---|
| Учёт | Только количеством (без поштучного учёта с номерами) |
| Кто меняет остатки | Специалист — только «взять»; координатор — приход, исправление, позиции, импорт |
| Структура | Категория (фиксированный список в коде) → позиция (название, заводит координатор) → остаток по состоянию |
| Состояния | новое / б/у / после ремонта |
| Что пишем при выдаче | Кто, что, сколько, когда — без привязки к заявке |
| Минимум | Необязательный минимум у позиции; уведомление координаторам при пересечении |
| Интерфейс | Внутри бота, кнопка «📦 Склад»; начальная загрузка — xlsx |

**Вне рамок:** поштучный учёт (инвентарные/серийные номера, «где стоит»), привязка выдачи к заявке/задаче, управление категориями из бота, фото позиций, голосовой ввод на складе, переименование категорий.

## 2. Данные

### Категории — `helpdesk/stock/catalog.py`

Фиксированный упорядоченный список `CATEGORIES: dict[str, str]` (код → подпись). Добавить категорию — одна строка в коде, без миграции (в БД хранится код, `String(24)`).

| Код | Подпись |
|---|---|
| `printers` | 🖨 Принтеры и оргтехника |
| `pc` | 🖥 Системные блоки |
| `monitors` | 📺 Мониторы |
| `cartridges` | 🖋 Картриджи |
| `cables` | 🔌 Кабели (VGA, HDMI) |
| `storage` | 💾 Диски (SSD, HDD) |
| `adapters` | 🔀 Переходники (сеть→USB и др.) |
| `hubs` | 🔗 USB-хабы |
| `headsets` | 🎧 Наушники |
| `batteries` | 🔋 Батарейки |
| `mice` | 🖱 Мыши |
| `keyboards` | ⌨️ Клавиатуры |
| `other` | 📦 Прочее |

`CONDITIONS: dict[str, str]` = `new` → «новые», `used` → «б/у», `repaired` → «после ремонта» (порядок фиксирован). В xlsx принимаются и подписи, и коды, без учёта регистра; «новое»/«новый» тоже.

### Таблицы (одна миграция)

- `stock_items`: `id`, `category` (`String(24)`), `name` (`String(200)`), `min_qty` (`int | None`), `archived` (`bool`, default false), `created_at`. Уникальность: `(category, lower(name))` — частичный уникальный индекс только для `archived = false` (в архиве может лежать позиция с тем же именем).
- `stock_levels`: `item_id` FK, `condition` (`String(16)`), `qty` (`int`, `CHECK qty >= 0`); PK `(item_id, condition)`. Строки создаются при первом приходе (insert … on conflict do nothing).
- `stock_moves`: `id`, `item_id` FK, `condition`, `delta` (`int`, ≠ 0), `kind` (`in` | `out` | `fix` | `import`), `staff_id` FK, `created_at`. Индекс по `created_at`.

### Сервис — `helpdesk/stock/service.py`

Все изменения остатка — только через сервис, в транзакции обработчика, с `SELECT … FOR UPDATE` строки `stock_levels`:

- `create_item(s, staff, category, name, min_qty) -> StockItem` — `DuplicateName`, если активная позиция с таким именем (без учёта регистра) уже есть в категории.
- `receive(s, staff, item_id, condition, qty, kind="in")` — `qty` 1…1000; создаёт строку уровня при необходимости.
- `take(s, staff, item_id, condition, qty) -> TakeResult(ok, left, available)` — если `qty > available` → `ok=False`, остаток не меняется.
- `set_level(s, staff, item_id, condition, new_qty)` — `fix`, в историю пишется разница; если разница 0 — ничего не пишется.
- `set_min(s, item_id, min_qty | None)`, `archive(s, item_id)`.
- `levels(s, item_id) -> dict[condition, int]`, `category_totals(s) -> dict[category, int]` (без архивных), `items_in(s, category, page)`, `search(s, text, limit=20)` (ILIKE по имени, без архивных).
- Порог минимума: после `take` и уменьшающего `set_level`, если `min_qty` задан и `total_before > min_qty >= total_after` (total — сумма по всем состояниям), каждому координатору `outbox.tg_send(text="⚠️ <название>: осталось N (минимум M)")`. При пересечении вниз — одно сообщение; повторное — только после того, как остаток снова поднимется выше минимума и опять упадёт.
- Архивная позиция: `take`/`receive`/`set_level` → `Archived`.

Права проверяются в сервисе (`NotCoordinator`) и в обработчиках (кнопки координатора не показываются специалисту). Координатор — `staff.role == "coordinator"`; админ без этой роли на складе — обычный специалист.

## 3. Интерфейс в Telegram — `telegram/stock_handlers.py`

Новая кнопка меню `STOCK = "📦 Склад"` для всех активных, отдельной строкой. Callback-префикс `sk_` (`sk_cat:<code>:<page>`, `sk_item:<id>`, `sk_take:<id>`, …); устаревшие кнопки диалога → «Диалог уже завершён», как у задач. FSM `StockForm` для ввода текста (количество, название, минимум, поиск, файл).

**Экраны**
1. «📦 Склад» → сообщение с кнопками категорий (по 2 в ряд, «<подпись> · <всего>»; пустые категории тоже показаны) и строкой `[🔍 Найти] [📥 Склад.xlsx]`, у координатора ещё `[➕ Новая позиция] [📤 Загрузить xlsx]`.
2. Категория → позиции по 10 на страницу, кнопка на позицию: «<название> — новые 7 · б/у 3» (только ненулевые состояния; все нули — «нет»), «⚠️» если total ≤ min. Пагинация ◀️ ▶️, «⬅️ Категории».
3. Карточка позиции: название, категория, остаток по трём состояниям, минимум. Кнопки: `[➖ Взять]` (если total > 0), у координатора `[➕ Приход] [✏️ Исправить] [🔔 Минимум] [🗄 В архив]`, `[⬅️ Назад]`.

**Сценарии**
- **Взять:** состояние (кнопки только состояний с qty > 0; если одно — шаг пропускается) → количество `[1] [2] [3] [Другое]` (кнопки > available не показываются; «Другое» → ввод числа) → `take` → «✅ Взято: <название> ×N (<состояние>). Осталось M.» Нехватка → «Осталось только K» и снова выбор количества.
- **Приход** (коорд.): состояние (все три) → «Сколько пришло?» число 1…1000 → «➕ <название> +N (<состояние>). Теперь M.»
- **Исправить** (коорд.): состояние → «Сколько сейчас на самом деле?» число 0…100000 → `set_level`.
- **Минимум** (коорд.): число 0…100000 или «Убрать».
- **В архив** (коорд.): подтверждение `[Да, в архив] [Отмена]`.
- **Новая позиция** (коорд.): категория → название (1…200 символов; дубль → «Уже есть» + `[Открыть]`) → минимум или «Пропустить» → дальше как «Приход».
- **Найти:** «Введите часть названия» → до 20 совпадений кнопками; нет — «Ничего не найдено».

Ввод чисел: только цифры; иначе «Введите число от A до B». В диалогах работают «✖️ Отмена», кнопки меню и команды (выход из диалога) — как в задачах; лишний ввод не уходит пользователю WhatsApp (`stray_input` склада).

## 4. xlsx — `helpdesk/stock/xlsx.py`

### Загрузка (координатор)
- «📤 Загрузить xlsx» → бот присылает шаблон `Склад-шаблон.xlsx`: лист «Склад» с колонками Категория · Название · Состояние · Количество · Минимум (+ две строки-примера), лист «Справка» со списком категорий и состояний.
- Координатор присылает файл (документ `.xlsx`, ≤ 2 МБ, иначе отказ). Чтение: `openpyxl.load_workbook(read_only=True, data_only=True)` — берутся только значения, формулы не исполняются; первый лист; первая строка — заголовок; не больше 1000 строк данных (иначе отказ целиком); пустые строки пропускаются.
- Каждая строка проверяется: категория — код или подпись (без эмодзи, без учёта регистра); название 1…200; состояние — см. §2, пусто → «новые»; количество — целое 0…100000; минимум — пусто или целое 0…100000.
- Итог (ничего ещё не записано): «Новых позиций: A, приход по существующим: B, ошибки: C» + до 10 первых ошибок «строка N: <что не так>». Кнопки `[✅ Загрузить (без ошибочных строк)] [✖️ Отмена]`. Разобранные строки хранятся в FSM (не файл).
- Применение: позиция ищется по (категория, название без учёта регистра) среди активных, иначе создаётся; количество > 0 → `receive(kind="import")`; минимум из файла (если указан) заменяет минимум позиции. Одна транзакция. Повторная загрузка того же файла прибавляет количество ещё раз — это написано в подсказке шаблона.

### Выгрузка («📥 Склад.xlsx», все)
- Лист «Остатки»: Категория · Позиция · Новые · Б/у · После ремонта · Всего · Минимум · «⚠️» (если total ≤ min). Архивные не выгружаются.
- Лист «Движение»: Дата (местное время через `clock.local`, как в текущей выгрузке) · Кто · Категория · Позиция · Состояние · Изменение (±) · Тип (приход / выдача / исправление / загрузка). Всё время, новые сверху.
- Текстовые ячейки — через существующий `_safe` (защита от формул) — вынести в общий модуль, не копировать.

## 5. Ошибки

| Ситуация | Ответ |
|---|---|
| Взять больше, чем есть (в т.ч. кто-то успел раньше) | «Осталось только K», выбор количества заново |
| Число не число / вне диапазона | «Введите число от A до B» |
| Дубль названия в категории | «Уже есть» + `[Открыть]` |
| Позиция в архиве (карточка была открыта) | «Позиция в архиве» |
| Кнопка координатора у специалиста | alert «Только для координатора» |
| xlsx > 2 МБ / > 1000 строк / не xlsx / битый | отказ с причиной, ничего не записано |
| Нет координаторов при пересечении минимума | уведомление никому не уходит, лог `stock low, no coordinators` |

## 6. Тестирование

TDD, тесты против тестовой Postgres (как сейчас).
- service: создание и дубль (в т.ч. разный регистр; архивный дубль разрешён); приход/выдача/нехватка; две одновременные выдачи последней штуки в двух сессиях — одна успешна, вторая «осталось 0», `qty` не < 0; `set_level` пишет разницу; порог — одно уведомление при пересечении, нет при уже низком, снова после подъёма; без координаторов — без outbox; архив блокирует изменения; права (`NotCoordinator`).
- xlsx импорт: корректные строки (код и подпись категории, синонимы состояний, пустое состояние → новые); ошибки по каждому полю с номером строки; лимиты строк и размера; формула в ячейке не исполняется; повторный импорт прибавляет; минимум обновляется.
- xlsx экспорт: оба листа, архивные не попадают, защита от формул, порядок.
- обработчики: меню «📦 Склад» у всех; кнопки координатора скрыты у специалиста и отвергаются при прямом вызове; полный сценарий «взять»; нехватка; «Другое» с вводом числа; новая позиция; поиск; пагинация; отмена/меню посреди диалога; лишний ввод не уходит в WhatsApp; устаревшие `sk_` кнопки.

Ручная проверка — пункты чек-листа README (новый раздел «Склад»).

## 7. Развёртывание

Одна миграция alembic; новых зависимостей нет (openpyxl уже есть). Кнопка «📦 Склад» появляется у всех после перезапуска (меню обновляется при следующем ответе бота).
