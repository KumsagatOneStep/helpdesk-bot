# Helpdesk-бот: WhatsApp → Telegram

Пользователи пишут на общий номер WhatsApp. Заявки приходят специалистам в Telegram,
первый нажавший «✋ Взять» получает заявку, у остальных она исчезает. Подробности:
`docs/superpowers/specs/2026-10-07-helpdesk-bot-design.md`.

## Что нужно

- VPS с Ubuntu (1 vCPU, 1–2 ГБ RAM) и Docker (`curl -fsSL https://get.docker.com | sh`).
- Отдельная SIM-карта с WhatsApp или WhatsApp Business на телефоне.
- Аккаунт Green API (green-api.com) и созданный инстанс.
- Telegram-бот, созданный через @BotFather (нужен токен).

## Установка

1. `git clone <репозиторий> helpdesk-bot && cd helpdesk-bot`
2. `cp .env.example .env` и заполнить:
   - `TELEGRAM_BOT_TOKEN` — токен от @BotFather;
   - `ADMIN_TG_IDS` — ваш Telegram ID (узнать у @userinfobot), через запятую;
   - `GREEN_API_ID_INSTANCE`, `GREEN_API_TOKEN`, `GREEN_API_URL`, `GREEN_API_MEDIA_URL` — из личного кабинета Green API (apiUrl и mediaUrl инстанса);
   - `POSTGRES_PASSWORD` — длинный пароль только из латинских букв и цифр (он подставляется в `DATABASE_URL`, спецсимволы вроде `@`, `:`, `/` сломают адрес);
   - `TASK_REMIND_HOUR` — час напоминаний о сроках задач, по умолчанию 9;
   - `STT_ENABLED`, `STT_MODEL`, `STT_MAX_SECONDS` — распознавание голосовых (локальный Whisper). Для `small` нужно от 4 ГБ RAM; первое голосовое скачивает модель (~500 МБ) в `data/models`. Образ бота — около 1.4 ГБ.
3. Папки и права (бот пишет от uid 10001, сервис бэкапа — от uid 999; в `.env` токены):
   ```bash
   mkdir -p data backups
   sudo chown 10001:10001 data && sudo chown 999:999 backups
   sudo chmod 700 data backups && chmod 600 .env
   ```
4. Green API: в кабинете отсканировать QR телефоном рабочего номера. В настройках инстанса включить
   «Получать уведомления о входящих сообщениях и файлах», поле Webhook URL оставить **пустым**.
5. `docker compose up -d --build`
6. Проверить: `docker compose logs -f bot` — без ошибок, бот отвечает на `/start`.
7. Админ пишет боту `/start`. Специалисты пишут `/start`, админ нажимает «✅ Одобрить».

## Обслуживание

- Логи: `docker compose logs -f bot` (ротация: 3 файла по 10 МБ на сервис)
- Обновление: `git pull && docker compose up -d --build` (миграции применяются при старте)
- Бэкапы базы: `./backups/` (ежедневно, 14 дней). Вложения лежат в `./data/files` —
  включите снапшоты диска у провайдера VPS или копируйте папку `data/` отдельно.
- Восстановление: `gunzip -c backups/daily/<файл>.sql.gz | docker compose exec -T db psql -U helpdesk helpdesk`

## Разработка

```bash
uv sync
make test-db   # PostgreSQL для тестов на localhost:5433
make check     # ruff + pytest
```

Тесты на VPS не запускать: тестовая база с известным паролем (хотя `make test-db` и слушает только 127.0.0.1).

## Чек-лист ручной приёмки

Нужны: рабочий номер, второй телефон (пользователь) и три Telegram-аккаунта (админ, Ерлан, Тимур).

1. [ ] Админ `/start` → «Вы в системе». Ерлан и Тимур `/start` → админу приходят запросы, оба одобрены.
2. [ ] С телефона пользователя «Не печатает принтер» → вопрос о языке; «1» → ФИО; ФИО → кабинет; кабинет → «Заявка #1 принята».
3. [ ] У всех троих появилась карточка #1 с ФИО, кабинетом, телефоном, текстом и кнопкой «✋ Взять».
4. [ ] Ерлан нажал «Взять» → у админа и Тимура карточка исчезла, у Ерлана кнопки «Закрыть / Вернуть», пользователю пришло «занимается Ерлан».
5. [ ] Тимур и админ почти одновременно жмут «Взять» на новой заявке → заявку получает один, второй видит «Уже взял …».
6. [ ] Пользователь шлёт фото → Ерлан получает фото с подписью `#1 · ФИО`.
7. [ ] Ерлан пишет текст и голосовое → пользователь получает оба в WhatsApp; Ерлану приходит «→ #1 … ✓».
8. [ ] Вторая заявка от другого номера у Ерлана; «Ответить» на сообщение заявки #1 уходит в #1, обычный текст — в активную; «Ответить» на сообщение без заявки (например, /my) — отказ, ничего не уходит.
9. [ ] «↩️ Вернуть» → карточка снова у всех на смене. «✅ Закрыть» → пользователю «Заявка выполнена»; новое сообщение создаёт новую заявку.
10. [ ] Заявку никто не берёт 10 минут → приходит «⏰ … ждёт 10 мин».
11. [ ] `/off` у всех → новая заявка: админу «на смене никого»; `/on` у Тимура → карточка приходит ему.
12. [ ] `/my`, `/open`, `/find 1`, `/find <ФИО>`, «Показать переписку» показывают верные данные.
13. [ ] `/stats` → цифры совпадают с реальностью; `/export` → Excel открывается, кириллица и даты корректны.
14. [ ] Казахский язык: новый номер, ответ «2» → все сообщения на казахском.
15. [ ] `docker compose restart bot` во время переписки → сообщения не теряются, отправка продолжается.
16. [ ] `/staff` → отключить Тимура с заявкой в работе → заявка вернулась в очередь, Тимур получает «Доступ закрыт».

### Внутренние задачи

Нужны: два helpdesk-специалиста (Ерлан, Тимур) и координатор (Айжан).

17. [ ] Админ в `/staff` нажал «🧭 Сделать координатором» у Айжан → в списке «Айжан · 🧭 координатор».
18. [ ] Ерлан: «➕ Новая задача» → Helpdesk → «Заменить картридж» → «каб. 214» → «Завтра» → «Создать» → «Задача З-1 создана». У Ерлана карточка с «Закрыть / 🆘 Нужна помощь», у Тимура и Айжан — без кнопок.
19. [ ] Ерлан: новая задача типа «Координатор» → карточка с «✅ Принять» только у Айжан (у Тимура нет). Айжан приняла → Ерлану «✅ Айжан принял(а) З-2».
20. [ ] Ерлан на З-1 жмёт «🆘 Нужна помощь» → Тимуру и Айжан (на смене) «🆘 Ерлан просит помощи» с «Взять». Оба жмут почти одновременно → взял один, второй видит «Уже взял(а) …».
21. [ ] «Ответить» на карточку З-1 → у остальных «💬 З-1 · …». При этом у Ерлана есть активная заявка WhatsApp — пользователю в WhatsApp ничего не приходит.
22. [ ] Посреди создания задачи нажать «📋 Мои заявки» → диалог прерван, показан список; «✖️ Отмена» на любом шаге → «Отменено».
23. [ ] Задача со сроком «Сегодня», созданная вчера (поправить `due_date`/`created_at` в БД) → в `TASK_REMIND_HOUR` приходит «⏰ Сегодня срок»; на следующий день — «⚠️ Просрочена» исполнителю и Айжан.
24. [ ] `/my`, `/open`, `/find З-1`, `/find картридж` показывают задачи; Тимур не находит задачу «Координатор», созданную Айжан для себя.
25. [ ] `/stats` — блок «📌 Задачи»; `/export` — лист «Задачи».
26. [ ] `/staff` → отключить Тимура с задачей в работе → задача у остальных на смене с «Взять».

### Голосовой ввод

27. [ ] «➕ Новая задача» → тип → голосовое «Заменить картридж в 214 кабинете» → первое голосовое: «⏳ Загружаю модель…», затем «🎤 Распознано: …» с кнопками.
28. [ ] «✅ Подходит» → шаг «Для кого»; задача создана с этим описанием, без аудио — только текст.
29. [ ] «✏️ Исправить» → можно прислать текст или новое голосовое.
30. [ ] Голосовое на казахском — текст распознан (оценить качество; при плохом — попробовать `STT_MODEL=medium`).
31. [ ] Голосовое длиннее 2 минут в описании → «напишите текстом».
32. [ ] «Ответить» голосовым на карточку задачи → остальным аудио с подписью «💬 З-… · Имя (🎤): текст», себе — «💬 → З-… ✓» и текст.
33. [ ] `STT_ENABLED=false` → голосовое в описании: «Распознавание выключено»; комментарий уходит аудио.
34. [ ] Длинное голосовое-комментарий (больше ~1000 символов текста) → у остальных аудио с короткой подписью и следом полный текст отдельным сообщением.
35. [ ] Пока голосовой комментарий распознаётся, другой специалист закрывает задачу → автору «З-… уже закрыта — комментарий не отправлен.», остальным ничего не приходит.
